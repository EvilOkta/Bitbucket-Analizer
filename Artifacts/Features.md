# Features (Функциональные возможности)

В данном документе фиксируются реализованные и запланированные функциональные модули системы анализа репозиториев Bitbucket в соответствии с техническим заданием.

## 1. Подключения и источники проектов
- [x] **Bitbucket Server / Data Center Connector**: Подключение к on-premise серверу Bitbucket через Personal Access Token (PAT), синхронизация проектов, репозиториев, веток и коммитов.
- [x] **Локальный выбор репозиториев (Local Folder / Offline Mode)**:
  - Нативный диалог выбора папки операционной системы (`dialog.showOpenDialog`).
  - Автоматическая проверка инициализации Git (поиск `.git`, чтение ветки из `.git/HEAD`, предупреждение `Без .git` при отсутствии).
  - Рекурсивный сбор файлов с фильтрацией мусорных каталогов (`node_modules`, `dist`, `bin/obj`, `__pycache__`, `.venv`, `.git`).
- [x] **Confluence Server / Data Center Connector**: Авторизация по PAT, публикация отчетов, архитектурных диаграмм и моделей данных.
- [x] **Локальная LLM (Qwen API)**: Интеграция с локально развернутой моделью Qwen по HTTP/OpenAI-compatible API с авторизацией по токену.
- [x] **Прямой анализ БД**: Read-only подключение к PostgreSQL для извлечения физической схемы (information_schema, DDL, таблицы, FK, индексы).

## 2. Анализ репозитория, Монорепозитории и Классификатор
- [x] **Поддержка монорепозиториев (Monorepo & Workspaces)**:
  - Автоматическая детекция структуры подпроектов (Nx, Turborepo, Yarn/pnpm workspaces, .NET Solutions `.sln`/`*.csproj`, Gradle multi-project, Maven submodules, Python services).
  - Селектор области анализа в шапке («Весь монорепозиторий» / конкретный подпроект `apps/web-client` / `services/order-api`).
- [x] **Классификатор и профилирование репозиториев (Repository Classifier & Similarity)**:
  - Вычисление структурной схожести (Jaccard similarity по AST, именам файлов, эндпоинтам и моделям данных).
  - Разделение репозиториев по ролям: `📦 Микросервис`, `🧬 Эволюционная копия / Версия (N% сходства)`, `🏗️ Монорепозиторий`, `📚 Shared Library`, `💻 Локальный`.
- [x] **Межрепозиторная и межмодульная трассировка связей (Cross-Service Contract Tracing)**:
  - Обнаружение исходящих REST HTTP-вызовов (`fetch`, `axios`, `HttpClient`, `httpx`) и событий брокеров сообщений (Kafka, RabbitMQ) между репозиториями/сервисами.
- [x] **Импорт и синхронизация**: Клонирование репозиториев через Git over HTTPS/SSH с PAT, выбор ветки/коммита, поддержка инкрементального анализа.
- [x] **Дерево проекта (Repository Explorer)**: Построение иерархической структуры файлов с многоуровневым поиском (по пути, стемму и вхождению интерфейсов/классов в тело файла).
- [x] **Детекция технологического стека**: Распознавание языков и фреймворков: **Python** (FastAPI, Django, Flask), **.NET / C#** (ASP.NET Core, EF Core), **JavaScript / TypeScript** (Node.js, Express, React, Vue), **C / C++** (CMake, Make, vcpkg), **PostgreSQL** (DDL, миграции).
- [x] **Рекомендации по структуре**: Rule-based и Qwen-assisted аудит архитектуры (выявление антипаттернов, смешивания слоев, отсутствия тестов).
- [x] **Интерактивный D3-граф проектов (4 режима представления + Монорепозитории и Версии)**:
  - **Режим 1 (Глобальный)**: `Bitbucket Server / Корневой сервер ➔ Ключи проектов` (`ENTERPRISE`, `CORE`, `PROJ`, `HIGH`, `LOCAL`).
  - **Режим 2 (Проектный)**: `Ключ проекта ➔ Репозитории` (с бейджами `🏗️ Монорепозиторий`, `🧬 Версия / Копия`, `📦 Микросервис`, `💻 Локальный`, а также отрисовкой пунктов эволюционных связей сходства `88% сходства` между версиями репозиториев).
  - **Режим 3 (Репозиторий & Монорепозиторий)**: `Репозиторий ➔ Подпроекты / Ветки` (автоматическое раскрытие подпроектов монорепозиториев `apps/web-client`, `services/order-api` и переключатель фильтра «Все» / «Подпроекты» / «Ветки»).
  - **Режим 4 (Ветка / Подпроект и коммиты)**: `Ветка / Подпроект ➔ Коммиты` (полная синхронизация каскадных селекторов Проект $\rightarrow$ Репозиторий $\rightarrow$ Подпроект/Ветка).
  - Бесшовный drill-down при двойном клике на ноды, цветовой градиент активности (от зеленого к красному) и расширенная боковая панель с деталями, списком подпроектов, метриками версий и кнопкой прямого запуска анализа.

## 4. Модель данных и ER-диаграммы
- [x] **Динамическая генерация логической модели без моков**:
  - Извлечение сущностей, атрибутов, первичных и внешних ключей из физических PostgreSQL DDL файлов и миграций (`CREATE TABLE`, `ALTER TABLE ... FOREIGN KEY`).
  - Парсинг схем Prisma (`*.prisma`).
  - Парсинг Python ORM моделей (SQLAlchemy `Column`, `ForeignKey` и Django `models.Field`, `ForeignKey`).
  - Парсинг .NET C# Entity Framework Core (`[Table]`, `[ForeignKey]`, `[Key]`, свойства классов).
  - Парсинг TypeScript / TypeORM сущностей, интерфейсов и типов данных.
  - **Парсинг JavaScript/TypeScript структур данных (Frontend Data Models)**: извлечение сущностей из объектных констант, маппингов (например, `nodesMap = { 'Корень': { ... } }`), фабрик графов, начальных состояний Redux/Zustand и коллекций объектов с детальной типизацией хранимых элементов (`INTEGER ARRAY`, `VARCHAR ARRAY`, `FOLDER SET`, `CATEGORY SET`, `FILE ARRAY`, `BOOLEAN`, `JSONB`) и извлечением описаний атрибутов (JSDoc, inline comments, `COMMENT ON COLUMN`, `/// doc`).
  - Построение логической модели на основе извлеченных API Request/Response DTO моделей при отсутствии физических схем БД.
  - **Специализированное представление ENUM в модели данных**:
    - Для сущностей типа ENUM устранены псевдо-реляционные колонки (`VARCHAR`, `PK`, `Nullable`, `val_1`). Ключом перечисления является его имя, а состав отображается в виде чистого списка допустимых значений с карточками/бейджами, таблицей литералов и перечнем ссылающихся сущностей.
  - **Интеллектуальное извлечение ENUM и структур из JS/TS**:
    - Распознавание литеральных объединений (union types) из комментариев и типов (например, `status: 'IDLE', // 'IDLE' | 'RUNNING' | 'PAUSED' | 'DONE' | 'STOPPED'`).
    - Извлечение структур объектов из аннотаций комментариев (например, `log: [], // Array of { timestamp, type: 'info'|'success'|'error'|'warning', text }` $\rightarrow$ сущность `LogItem` + `LogTypeEnum`).
    - Извлечение структур для массивов ошибок (`errors: [], // Array of { file, error }` $\rightarrow$ сущность `ErrorItem`).
    - Точный построчный разбор строчных комментариев после запятой (`log: [], // comment`), исключающий потерю контекста и перенос комментариев на чужие свойства объекта.
    - Скобочно-сбалансированный парсинг многострочных массивов строковых литералов (например, `capabilities: [ '...', '...' ]` в `TOOLS_CONFIG`), исключающий потери значений при переносе строк.
  - **Обновленная компоновка интерфейса ER-модели (Sidebar + Тоггл «Таблица» / «Визуализация»)**:
    - Постоянный сворачиваемый левый фрейм со списком таблиц, ENUM и системных сущностей, поиском и фильтрами (`Все`, `Таблицы`, `ENUM`, `Системные`).
    - Верхний сегментированный тоггл: **«Таблица»** (подробный состав колонок или чистый список значений ENUM) и **«Визуализация»** (интерактивный D3 граф или Mermaid диаграмма).
    - Автоматическая плавная фокусировка и центрирование D3 графа связей на таблице, выбранной в левом фрейме.
  - **Отображение источника / метода классификации сущности**: для каждой сущности выводится точный бейдж источника (`База данных (SQL DDL)`, `Prisma Schema`, `Python ORM`, `.NET EF Core`, `TypeScript Интерфейс`, `JavaScript Структура`, `API DTO`, `ENUM Перечисление`, `Системный тип`).
  - **Переход к исходному коду сущностей и колонок (Source Navigation)**: в списке таблиц, в заголовке инспектора выбранной сущности и в строках атрибутов отображаются ссылки и кнопки перехода с подсветкой строки объявления в Explorer с возможностью возврата.
- [x] **Визуализация ER-диаграмм**: Интерактивный холст D3 force simulation с плавным центрированием на выбранных сущностях, Mermaid ERD диаграммы с комментариями колонок, PlantUML ER-диаграммы (визуализация и код с темами `entity` и `enum`), табличный инспектор с быстрыми фильтрами по источникам (Все, Таблицы, ENUM, Системные), FK навигацией, описаниями атрибутов и переходом к коду, режим окружения таблицы, полноэкранный режим.
